# 이슈 작성

사용자가 제공한 요청과 저장소의 관련 코드, README, 이슈 템플릿을 확인한다. GitHub 조회가 가능하면 관련 이슈를 검색해 중복 또는 연관 항목을 확인한다. 연결 도구가 없으면 로컬 문안 준비는 계속한다.

- 버그는 발생 조건, 최소 재현 단계, 기대 동작, 실제 동작, 관련 환경과 필요한 로그를 정리한다. 로그에서 API 키·토큰·비밀번호·사내 개인정보를 제거한다. 오류 메시지만으로 원인을 확정하지 않는다.
- 기능 요청은 사용자 문제, 원하는 동작, 범위와 확인 가능한 완료 조건을 정리한다. 요청하지 않은 구현이나 대규모 구조 변경을 완료 조건으로 추가하지 않는다.
- RAG 이슈에는 해당 질문·분야·컬렉션, 문서 적재 상태, 적재·검색 임베딩 설정, 검색 결과와 답변 중 어느 단계의 문제인지 관련 정보만 포함한다. 모르는 정보는 확인 필요로 표시한다.
- 제목은 한국어로 구체적으로 작성하고, 저장소 이슈 템플릿과 라벨 관례를 따른다. 커밋 타입과 gitmoji를 이슈 제목에 강제하지 않는다.
- 문안 작성 요청이면 검토 가능한 문안을 제공한다. 생성·수정 요청이면 인증된 gh CLI 또는 사용 가능한 GitHub 도구로 수행한다. 라벨·담당자는 요청이나 저장소 관례에 근거해서만 지정한다.
- gh의 여러 줄 본문은 임시 파일로 저장해 --body-file로 전달한다. 생성 전 중복 이슈를 확인한다. 생성 실패 시 성공 여부를 먼저 확인하고 무작정 재시도하지 않는다. 요청 없이 다른 이슈를 닫지 않는다.

완료 시 이슈 링크 또는 준비된 문안과 확인이 필요한 정보만 간결하게 보고한다.
