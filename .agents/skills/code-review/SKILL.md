# 코드 리뷰

사용자가 지정한 파일·커밋·PR 범위를 우선한다. 범위가 없다면 Git 상태와 변경 diff를 확인하고 검토한 범위를 명시한다. AGENTS.md와 저장소 지침이 있으면 적용한다.

변경 코드와 필요한 호출부를 함께 읽고 실제로 발생할 수 있는 결함을 찾는다. 아래 항목은 관련 변경에서만 확인한다.

- 도구 팩토리와 @tool의 등록 방식, 고유한 도구 이름, 인자 스키마 및 반환 타입.
- 분야와 PGVector 컬렉션의 일치, 적재·검색 임베딩 모델과 차원의 일치, 검색 결과 없음과 근거 없는 답변 처리.
- document_prompt가 요구하는 metadata의 존재, 출처 누락 또는 페이지 번호의 잘못된 변환, 문서 지시문을 행동 규칙으로 취급하는 문제.
- 환경 변수 누락·포트 검증·특수문자 URL 처리, import 시점 기본 인자 생성, DB/API 오류와 비밀 정보 노출.
- PDF 상대 경로, 토큰 분할 설정, 반복 적재 중복 및 사용자 데이터 보존.

현재 코드나 설치된 라이브러리에서 사실을 확인한다. 의미 있는 최소 검증을 수행하되 실제 API 비용이나 DB 변경이 필요한 검증은 기존 승인 범위 안에서만 실행한다. 필요하면 모의 검증을 사용하고 그 한계를 적는다.

발견사항은 심각도 순으로 파일·줄 번호, 발생 조건, 영향, 권장 수정 방향을 함께 보고한다. 확정된 결함과 추가 확인이 필요한 가정을 구분한다. 취향이나 포맷 차이를 버그로 보고하지 않는다. 문제가 없으면 그 사실과 검토·검증 범위를 명시한다.

리뷰 요청만으로 코드를 수정하거나 GitHub 리뷰를 게시하지 않는다. 수정 또는 게시를 명시적으로 요청받으면 그 범위에서 수행한다.
