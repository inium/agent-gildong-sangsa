# PR 작성

현재 저장소의 README, AGENTS.md(있는 경우), PR 템플릿과 커밋 규칙을 먼저 확인한다. 저장소 이름이나 기본 브랜치를 하드코딩하지 않는다.

- Git 상태와 원격, 대상 브랜치를 확인하고 merge-base 이후 diff를 검토한다. 커밋되지 않은 변경과 PR에 포함될 커밋을 구분한다. 다른 작업자의 변경을 임의로 포함하지 않는다.
- 제목은 프로젝트의 Conventional Commits와 gitmoji 규칙을 따른다. 예: `feat(RAG): ✨ 복리후생 검색 도구 추가`. scope는 현재 설정에 맞춘다.
- 본문은 해결하는 문제와 변경 후 동작으로 시작한다. 저장소 템플릿이 있으면 사용하고, 변경 이유·주요 변경·검증 결과·실질적 제한 사항을 한국어로 간결하게 작성한다.
- RAG 변경은 컬렉션, 적재·검색 임베딩 일치, 검색 결과와 출처에 미치는 영향을 필요한 만큼 설명한다. 실제 OpenAI/DB 검증, 모의 검증, 실행하지 않은 검증을 명확히 구분한다. API 키나 접속 URL의 비밀번호를 출력하지 않는다.
- 현재 변경에 필요한 검사만 실행한다. 문서 변경에는 diff 검사를, 동작 변경에는 관련 검증을 사용한다. 검증하지 않은 결과를 성공으로 기록하지 않는다.
- PR 문안만 요청받았다면 문안을 제공한다. PR 생성·수정 요청이면 인증된 gh CLI 또는 사용 가능한 GitHub 도구로 완료한다. 승인된 범위의 push가 필요하면 진행하며, 요청 없이 merge하거나 기존 PR을 닫지 않는다.
- gh의 여러 줄 본문은 임시 파일에 저장해 --body-file로 전달한다. 생성 전에 기존 PR을 확인해 중복을 피한다. 권한 오류가 나면 인증 계정과 원격을 확인하고, 임의로 fork를 만들거나 원격을 변경하지 않는다.

완료 시 PR 링크 또는 준비된 문안, 검증 결과와 남은 제한 사항을 보고한다.
